# Implementation Approval — Enforced Rules

1. MUST request explicit permission before architecture changes
2. MUST request explicit permission before adding new features
3. MUST request explicit permission before switching technologies or frameworks
4. MUST request explicit permission before major refactoring
5. NEVER change implementation immediately when user asks "why" — explain first
6. ALWAYS suggest possible actions and wait for user choice on high-level decisions
7. MUST proceed naturally for implementation details (files, methods, CRUD endpoints, tests, configs)
